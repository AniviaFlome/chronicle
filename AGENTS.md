# AGENTS.md — Chronicle

Flutter student planner. NixOS-first repo; `flutter`/`dart` only exist inside `nix develop`.

## Shell / build
- Always run via `nix develop --command bash -c "..."` from repo root.
- Linux bundle: `nix develop --command bash -c "flutter build linux --release"`. devShell sets `SQLITE_LIB` + `LD_LIBRARY_PATH` for drift. Release tarball bundles `libsqlite3.so` under `bundle/lib` (found via `$ORIGIN/lib` RUNPATH — no launcher script, no system sqlite needed).

## Release
- Version lives in `pubspec.yaml` (`versionName/versionCode`). Push tag `vX.Y.Z` to publish.
- Android signing reads `CHRONICLE_KEYSTORE` (+`_PASSWORD`, `_ALIAS`, `_KEY_PASSWORD`) from env; without them builds fall back to debug keys. Upload keystore lives in `android/keystore/` (gitignored) — never commit it; CI restores it from `ANDROID_KEYSTORE_BASE64`.
- `ci.yml` runs analyze + tests on push/PR. `release.yml` runs on tags: verify, signed universal APK + Linux tarball + AppImage + Flatpak, GitHub Release with `CHANGELOG.md` `[Unreleased]` notes.
- Linux Flatpak (`packaging/flatpak/*.yml`): `type: dir` sources merge their *contents* into the module build dir — the `dest: stage` on the source is what makes the `stage/...` paths in `build-commands` exist.
- Keep `CHANGELOG.md` `[Unreleased]` current; move entries under the version heading when tagging.

## Verify
- `nix develop --command bash -c "flutter analyze --no-pub"`
- `nix develop --command bash -c "flutter test --no-pub"` (all of `test/`, incl. `e2e_*` full-app suites)
- Single test: `--plain-name 'Exact test name'` — one flag only; multiple AND-match to zero.
- Keep full-app suites as plain `flutter_test` widget tests under `test/` (never an `integration_test/` dir: the flutter tool treats that path as on-device tests and tries to build + launch the Linux app, which needs GTK and a display that CI verify jobs don't have).
- Ignore drift "multiple databases" warnings in tests (each test makes its own `NativeDatabase.memory()`).

## On-device dev testing (side-by-side debug flavor)
- Debug builds install next to release: `applicationIdSuffix = ".debug"` in `android/app/build.gradle.kts` + `android/app/src/debug/AndroidManifest.xml` overlay (label `Chronicle Dev`, `tools:replace`). Ids in `.env` (`CHRONICLE_DEV_APP_ID`, `CHRONICLE_TEST_DEVICE`, `CHRONICLE_SYNC_FOLDER`).
- Same namespace/classes under both flavors, so the Dart push MUST use `qualifiedAndroidName` with fully-qualified receiver names (`WidgetReceivers` in `lib/services/widget_push.dart`); bare `androidName` resolves against the applicationId and throws `-3` on debug, failing the whole push silently (caught + debugPrint only).
- Never call `updateWidgetPreview` in the push loop: preview renders run full Glance compositions on the main thread per widget and wedge the method channel for tens of seconds (startup ANRs, subsequent pushes never sent). Gallery previews keep system cadence.
- Seed the dev app via `run-as $CHRONICLE_DEV_APP_ID` (`files/chronicle.sqlite`, `settings` keys `data_folder_path` + `auto_sync=false`), then manual Import in Settings → Data folder. Keep dev auto-sync OFF: two writers on one sync folder churn.
- Widget instances are placed by hand; verify with `dumpsys appwidget` (bindings carry the package, distinguishes Dev vs release), `logcat` (`Trying to notify widget update`, `Home widget refresh failed`, `Error in Glance App Widget`), screencap. Fresh-install cold starts ANR under dexopt load — force-stop + relaunch before concluding anything.
- Debug APKs install with `adb install -r` (different package: no signature clash with release). Never uninstall the user's release app for testing.

## Codegen — do not edit generated files
- `lib/data/database.g.dart` from `database.dart` + `tables.dart` via `dart run build_runner build --delete-conflicting-outputs`. Bump `schemaVersion` + idempotent `_addColumnIfMissing` steps (killed migrates must re-run safely).
- l10n source is `lib/l10n/app_en.arb` / `app_tr.arb` (`l10n.yaml`); generated `app_localizations*.dart` via `flutter generate`. Add strings to ARBs only.

## Architecture
- Entry `lib/main.dart`: opens `AppDatabase`, reads `calendarView`/`absencesView` prefs, overrides `*ViewSeedProvider` before `runApp` (avoids list→grid flash), applies portrait lock. `StartupRunner` does post-frame reminder sync + `warmCalendarWeek` + folder-sync start only — never read providers synchronously during mount.
- `lib/app.dart`: `go_router` `ShellRoute` (`/`, `/calendar`, `/classes`, `/tasks`, `/absences`, `/menu`, `/settings`). `NavigationRail` at width ≥600 (extended ≥900); custom `_PhoneNavBar` below 600 (stock `NavigationBar` can't fit 7 labels).
- State: hand-written Riverpod in `lib/providers.dart` — `riverpod_annotation`/`riverpod_generator` are deps but no `@riverpod` codegen is in use. Settings (`SettingsRepository`) is source of truth → `dayRangeProvider`/`fixedGridProvider`/`weekStartDayProvider`/etc. Calendar first paint is gated on warmed week inputs (`warmCalendarWeek`); add new geometry-affecting settings there.
- Schedule: `ScheduleRepository.loadEngine` → `domain/schedule_occurrence_engine.dart`.
- Themes (`lib/theme.dart`, 6 families: default/catppuccin/nord/dracula/gruvbox/tokyo-night): class fills must use `classBlockColor`, side-bars `classAccentColor`, text `classOnBlockColor` — never raw `Color(colorValue)`.
- Dining menu (`lib/services/menu/`, `/menu`): `MenuProvider` + `menuSources` registry (`hacettepe`, `itu`). Page is empty until a source is picked in Settings (`menu_provider` key, default ''). 6h cache in `MenuCache` table, excluded from sync/backup.
- Local data folder (`lib/services/data_folder.dart` + `folder_sync.dart`, started post-frame in `main.dart`): one JSON per table (`manifest.json`, `<table>.json`, `tombstones.json`) + `files/<stem>_<shortid>.<ext>` blobs for class/year attachments (blob bytes copied locally on import, incoming absolute paths never trusted). Merge is newer-`updatedAt`-wins keyed on `uuid`, deletes via `SyncTombstones`; conflicts preserved under `conflicts/`. Auto-sync (default on, `auto_sync` key): 5s-debounced merge-before-export on drift `tableUpdates()` (synced tables only), equality-gated import (manifest `exportedAt` + file mtimes — never wall-clock ordering) every 30s + at startup + on folder FS events + on app resume. Auto-export never prunes blobs; manual Export does.

## Home widgets (Android only)
- No codegen: `home_widget/*.dart` schemas and `lib/src/home_widget/` are gone (the generator is deleted). Kotlin is hand-written: shared `widget/` package (`WidgetTheme`/`WidgetData`/`WidgetComponents`/`WidgetCallbacks`/`VerticalWidgets`) + the 6 `GlanceAppWidget`s/receivers in `com.chronicleapp.chronicle` (class names are manifest contract: `NextClass`, `TodayAgenda`, `DueTasksCompact`, `ChronicleHub`, `CafeteriaMenu`, `WeeklyCalendar` + `*HomeWidgetReceiver`). Hub class tab and standalone Next-class render one shared `SharedClassTab` (hub stays pixel-identical by construction); `VerticalShell` has an optional flush `bottomBar` slot for bottom-pinned bars (null = legacy padded tree, other widgets unaffected).
- Wire contract is lockstep: `lib/services/widget_push.dart` `WidgetKeys` ↔ `widget/WidgetData.kt` `Keys` (prefs namespace `home_widget.<Widget>.<key>`). JSON strings via `HomeWidget.saveWidgetData<String>`; class colors travel as hex STRINGS ("FFRRGGBB" — never ARGB ints, that crashed Glance); `themeBg` is a 0..11 code (`familyIndex*2+darkBit`) mapped by `WidgetTheme.kt` `THEME_TABLE` and computed in `home_widgets.dart` — change both together. `useYou` (Settings widget style) now really toggles Material-You palette vs app-theme palette via `resolvePalette`.
- Push model (`lib/services/home_widgets.dart` → `widget_push.dart`, Android-guarded so tests are unaffected): `refreshHomeWidgets` runs at startup, on resume, and after class/task/theme saves; save-ALL then update-ALL. `timedData` keys are display-from times (start-of-today first, then previous class end), not class starts — native shows the greatest key ≤ now, closing '—' sentinel → `staleClassName`; `todayIso` mismatch gates stale. Each timed entry carries its own `looks` rows (hub lookahead follows the hero). Agenda day selection resets via pushing `selectedDay: 0`; hub `selectedTab` is native-owned (position in the enabled list, wrap-around). `scheduleWidgetTimelines` arms boundary + hourly + midnight updates for the NextClass and Hub receivers.
- l10n for pushed copy: ARB keys `widget*` in `lib/l10n/app_en.arb`/`app_tr.arb`, regenerate with `nix develop --command bash -c "flutter gen-l10n"` (`flutter generate` is deprecated and skips l10n). Widget picker names/descriptions stay in `res/values{,-tr}/home_widget_*.xml`.
- Debug APK needs a JDK the devShell lacks: `export JAVA_HOME=$(nix build nixpkgs#temurin-bin-17 --print-out-paths --no-link)` then `nix develop --command bash -c "flutter build apk --debug"`. Gradle "success" in seconds can be stale — verify by installing and looking at the device, never by timestamps alone.
- Glance 1.2.0 package facts (all paid for in build failures): `ActionCallback` + `actionRunCallback` live in `androidx.glance.appwidget.action`; `ActionParameters` + `actionParametersOf` stay in `androidx.glance.action`. `glance.color.ColorProvider(day, night)` is a top-level factory FUNCTION — callable but illegal as a type annotation (use the `unit.ColorProvider` interface for types). `Color(Int)` is ARGB; `Color(ULong)` is an already-packed color — never pass raw ARGB as ULong (renders garbage/crashes). `defaultWeight` is a `RowScope` member (no import exists). Glance `Text` has no `textAlign` param (`TextStyle` does). `Column`/`Row` silently drop past ~10 children. Read prefs in `provideGlance` via `HomeWidgetPlugin.getData(context)` — `currentState<HomeWidgetGlanceState>().preferences` is `@Composable` and will not compile there. RemoteViews forbids bare `<View>` in static preview layouts (use `ImageView`); preview layouts are hand-written RemoteViews-safe XML matching `WidgetData.Samples`.
- Glance `background()` REJECTS custom `ColorProvider` implementations — the RemoteViews translator logs `Unexpected background color modifier: <class>` and silently drops the fill (whole tonal chips/pills/hairlines vanish while real theme providers render fine). Always resolve color mixes EAGERLY to ARGB in `WidgetTheme.kt` and wrap in `fixedProvider`/`dayNightColor(...)` (a real Glance provider) before passing to `background()`.
- Framework RemoteViews size-maps pick the smallest entry that COVERS the requested size (w≥ && h≥). If nothing covers it, the host logs `Could not find a RemoteViews fitting the current size` and falls back to the nearest entry STRETCHED (wrong tier, oversized text). `SizeMode.Exact` composed at the provider's `minWidth/minHeight` only, so real 2×2 footprints (~302×210dp) never matched — use `SizeMode.Responsive` with near-real slots (`widgetSizeSlots` in `WidgetComponents.kt`; Glance 1.2 `Responsive` takes a `Set<DpSize>`, not a vararg).
- Glance session lifecycle (all paid for with measurements): `provideContent` sessions live ~45s BY DESIGN (documented) — "Closing session" ~45s after a tap is normal bookkeeping, never a latency signal. Measure tap→render with pre/post screenshots (+3s/+10s) and pixel-diff (`magick compare -metric RMSE`), never session-close timestamps. `update()` on a live session only flags recompose without restarting `provideGlance`, and pure `SharedPreferences` reads are invisible to the Compose runtime — recomposes replay the previously resolved state and taps look dead. Every native widget write must bump a snapshot counter read inside `provideContent` (`hubNavBump`/`agendaNavBump`/`menuNavBump` in `WidgetCallbacks.kt`, resolved via the `navBump` params).
- Glance composition rules: multi-root content (title + rows + indicator) must be invoked inside a vertical `Column` — bare multi-root siblings paint on top of each other. Same for lazy items: every multi-node `items { }` body wraps in its own `Column`, or gap spacers collapse to zero. `LazyColumn` needs `defaultWeight()` against a bounded shell (wrap-content lists measure only their first item); `defaultWeight` is a Row/Column-scope member, so a bare weight at top-level function scope doesn't compile — wrap in a plain `Column` first. Glance 1.2 ships NO `LazyRow` (only `LazyColumn`/`LazyVerticalGrid` — verified in the AAR), so horizontal rails use fixed windows, never scrolling lists.
- Narrow slots: `isNarrowSlot()` (`LocalSize.width < 200.dp`, `VerticalWidgets.kt`) gates compact type/counts/pills — wide layouts must stay pixel-identical. Resize floors live in `res/xml/*_info.xml` (`minResizeWidth/Height`, hub 200×150 down to tasks 180×110); floors constrain future resizes/placements only, never existing instances.
- On-device loop (Waydroid, `adb connect 192.168.240.112`): `waydroid session start` must run as a BACKGROUND shell with NO timeout (a `timeout` wrapper kills the session); `waydroid app install <apk>`; cold start requires force-stop + `waydroid app launch` (merely focusing a running app runs no startup push); verify with `adb screencap`, `dumpsys appwidget` (bindings + providers), `logcat` (`Error in Glance App Widget` + stack). The launcher sometimes drops widget bindings on reinstall and caches picker previews — re-add instances by hand before concluding anything is broken. Reinstalls renumber `appWidgetId`s and reshuffle the home layout — always re-dump (`uiautomator dump`) for fresh tap coordinates right before tapping; stale coords silently hit the wrong target (whole-widget tap opens the app). `uiautomator dump` forks a JVM per run, so keep dumps out of timing windows.
- Portrait-phone testing: `adb shell wm size 1080x2400` + `adb shell wm density 440` (verify with a screenshot), reset with `wm size reset` / `wm density reset` when done — config changes rebind widgets and can wedge the container (binder death, `offline`, `No route to host`); recover with `waydroid session stop` + fresh background `session start` + `adb connect`. The container also degrades on its own (45s+ IPC stalls, dead input dispatch with zero log output); identical inputs alternating between working and vanishing, or a tap with zero callback/session/log trace, means the environment — not the code.

## Hard rules (past bugs)
- Dates: never `Duration(days: n)` for calendar days (DST drift). Use `shiftDays(d, n)` / `DateTime(y, m, d + n)` (`lib/utils/time_format.dart`). Same for absence weeks and `TaskRepository.nextRepeatDate`.
- Day range is minutes (`day_start_minutes`/`day_end_minutes`, `dayRangeProvider`). Legacy `day_start_hour` keys remain as fallback; setters write both.
- Absence matrix weeks respect `weekStartDayProvider`; W1 = week containing `year.startDate`.
- Every insert stamps `uuid: newUuid()` + `updatedAt: syncNow()`; every update bumps `updatedAt`; every delete `recordTombstone`s the row plus cascade children *before* deleting (FK cascades won't tombstone). New tables need both columns + migration entries or sync silently duplicates rows.
- Tests: pump async-init screens with `pumpForAsync(tester)` helper (`test/widget_test.dart`); set `tester.view.physicalSize` for form/phone screens. `testWidgets` runs in FakeAsync: wrap ALL real async I/O (drift queries, `Directory`/`File` ops, folder export/import) in `tester.runAsync` — outside it they hang until the 10-min timeout (plain `test()` is unaffected).
- Linux window (`linux/runner/my_application.cc`): keep resizable + 800×600 minimum.
- Release builds minify (R8): Glance instantiates widget `ActionCallback`s reflectively, so `android/app/proguard-rules.pro` must keep every `*Callback` (+ its `<init>`) — stripped constructors crash ALL widget taps with `NoSuchMethodException` on release only (debug never minifies, so the breakage is invisible locally).
